## 1. Release overview

v0.23.0 closes **Milestone 18 — Budget-First Engine**.

When a budget is set and every package is over budget, users can explore nearby date pairs (±1–3 days), see scout “from €X” chips, and load a full search for a selected pair — without inventing understated round-trip prices.

Users still see informational estimates only. No booking checkout, payment, AI/LLM personalization, nearby airports, or trains/buses in this release.

---

## 2. Milestone 18 objective

Make **budget + flexible dates** a first-class path when Exact dates are too expensive:

1. Choose Exact or ±1 / ±2 / ±3 on the search form
2. See a clear CTA (or Exact hint) when packages exceed budget
3. Explore nearby dates via one dedicated API (rate-limited + kill-switchable)
4. Pick a date chip and load full packages for that pair
5. Keep SerpAPI costs honest and documented (250 searches/month plans)

---

## 3. Flexible dates + cheaper-options CTA

- Search form control: **Exact** / **±1** / **±2** / **±3** (URL `flex`)
- When budget is set and all same-currency packages exceed it:
  - flex 1–3 → **Find cheaper options**
  - Exact → hint to edit search and enable ± days
- Whole-trip date shift (same length of stay), not independent outbound/return flex

---

## 4. Explore API + scout

- **`POST /api/search/date-options`** — scout explore for flexible date pairs
- Separate rate limit from `/api/search` (tighter: explore fans out to many SerpAPI calls)
- **~15-minute** in-memory server cache per instance
- Kill switch: **`EXPLORE_DATES_ENABLED`** (`false` / `0` → 503 `EXPLORE_DISABLED`)
- Scout mode: flights + hotels only; SerpAPI scout does **1 outbound + 1 return** lookup so chip totals are real round-trip prices (plus 1 hotel ≈ **3** SerpAPI calls per pair)

---

## 5. Date price strip + chip selection

- Horizontal strip: **Your dates** + explore chips (earliest-first)
- Chip copy: short date range + **from €X** (estimates) + ✓ when `fitsBudget`
- Non-ok statuses: “No trips found” / “Couldn't check” (not selectable)
- Chip click → one normal `POST /api/search` for that date pair; URL dates update; flex kept
- Cost guards: re-click selected chip does nothing; client TTL cache reuses prior fetches; chips disabled while loading
- Honesty note when full-search cheapest exceeds the scout chip estimate

---

## 6. Price honesty + results fixes (Sprint 18.8)

- In SerpAPI Google Flights **round-trip**, the outbound option price is **not** the round-trip total
- True total arrives only via **`departure_token` return lookup**
- Full search: up to **3** return lookups; offers without enrichment are **dropped** (not shown understated)
- Failed return lookups are dropped for the same reason
- One-way searches unchanged (single outbound call)
- Browse Flights / Hotels: if nothing fits the budget, initial max price uses the **observed range** so lists are not empty while packages still warn
- Sort bar moved under Recommended Packages; label **Sort browse results**

See **ADR-038** in [DECISIONS.md](../DECISIONS.md).

## 7. SerpAPI cost (approximate)

Typical plan limit: **250 searches/month**. Prefer mock providers in development.

| Action | Approx. SerpAPI calls |
|--------|------------------------|
| Round-trip search (full) | ≈ **5** (1 outbound + up to 3 return + 1 hotel) |
| Explore ±1 | ≈ **6** (2 pairs × 3) |
| Explore ±2 | ≈ **12** (4 pairs × 3) |
| Explore ±3 | ≈ **18** (6 pairs × 3) |
| Chip click (full search) | ≈ **5** |

Live validation (Milan→Paris, ±1, live SerpAPI): chip **from €399** matched full search **€399** (pre-18.8 chip was **€215** vs **€399**). Explore ~10s; check used **4** SerpAPI searches.

## 8. Known limitations

- Monthly SerpAPI quota — explore ±3 is expensive; use the kill switch under pressure
- Fewer flight cards when many outbounds lack return enrichment (honesty over completeness)
- Same-airline near-duplicates in package top 5 (carry-forward)
- Destinations / About pages still not built
- Booking / payment / AI / nearby airports / trains & buses remain out of scope for M18
- currencyService DI debt (ADR-035); hotel `children_ages` default `8`

---

## 9. Security status

- Explore route has its **own** rate limit bucket (independent of `/api/search`)
- `EXPLORE_DATES_ENABLED` kill switch for quota emergencies
- Provider secrets remain server-only; no browser → SerpAPI calls
- Auth / RLS / CSP baseline unchanged in intent
