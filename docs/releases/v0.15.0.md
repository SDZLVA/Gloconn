## Highlights

- **Multi-provider flights architecture** — factory selects `mock`, `amadeus`, or `serpapi` behind one `FlightsProvider` contract
- **SerpAPI Google Flights integration** — full adapter package for development and testing (ADR-036)
- **Provider abstraction unchanged** — UI, orchestrator, and `Flight` / `SearchRequest` models stay vendor-neutral
- **Shared timeout infrastructure** — `lib/api/httpTimeout.ts` reused by SerpAPI (Amadeus keeps its existing helpers)
- **Factory integration** — `FLIGHTS_PROVIDER=serpapi`; invalid names fail fast with `ProviderError`
- **Testing improvements** — unit, provider, factory, and end-to-end integration suites with mocked HTTP only

## Migration notes

Default local/CI behavior is **unchanged**: `USE_MOCK_PROVIDERS=true` → mock flights.

To use SerpAPI for **dev/test** live-shaped results:

```env
USE_MOCK_PROVIDERS=false
FLIGHTS_PROVIDER=serpapi
SERPAPI_API_KEY=your_key
SERPAPI_DEEP_SEARCH=false
```

To use Amadeus (long-term production path):

```env
USE_MOCK_PROVIDERS=false
FLIGHTS_PROVIDER=amadeus
AMADEUS_API_KEY=
AMADEUS_API_SECRET=
AMADEUS_ENV=test
```

- Live mode with **no** `FLIGHTS_PROVIDER` defaults to **amadeus**.
- Unknown `FLIGHTS_PROVIDER` values throw `ProviderError` (no silent fallback).
- Missing vendor keys fall back to **mock** with a console warning (same pattern as Amadeus).
- No changes to `Flight`, `SearchRequest`, or search orchestration APIs.

## Known limitations

- **SerpAPI is temporary** — development/testing only; not the production inventory source of record (ADR-036)
- Round-trip return legs may need a second SerpAPI request (`departure_token`); v1 maps outbound-focused options
- `SERPAPI_DEEP_SEARCH=true` increases latency and timeout risk — default **false**
- Partial provider failure (one domain fails entire search) remains backlog
- `currencyService` still bypasses registry DI (ADR-035 debt)
- Manual Amadeus sandbox checklist not yet executed as a formal QA pass
- CI never calls live Amadeus or SerpAPI

- Partial provider failure so hotels/transport can succeed if flights fail

- **Amadeus Enterprise** as production flights inventory
- Additional flights vendors as needed (same `FlightsProvider` guide)
- AI travel optimization on top of stable provider outputs
