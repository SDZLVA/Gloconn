## 1. Release overview

v0.21.0 closes **Milestone 16 — Recommendation Intelligence**. Recommended Packages become more useful and easier to understand: better candidates before scoring, a diversity pass after scoring, and deterministic role labels with honesty gates.

Users still see informational estimates only. No booking, payment, AI/LLM personalization, new providers, or transport expansion.

---

## 2. Milestone 16 objective

Make the top Recommended Packages:

1. Higher-quality combinations (not clone grids of one flight or one hotel)
2. Visibly diverse in the first five cards when the provider pool allows it
3. Explainable without showing opaque numeric Match scores

Architecture remains locked:

```
Flights + Hotels
  → PackageComposer (candidate selection → compose → score → diversity)
  → TravelPackage[]
  → UI (top 5 visible + explainability roles)
```

No PackagesProvider. No scoring-weight redesign. No model/API/provider changes for this milestone.

---

## 3. Candidate quality improvements (Sprint 16.2)

- Flight quality slots use **stops + duration** (never `Flight.rating` — SerpAPI leaves it at 0)
- Hotel quality slots use **stars + guest rating + price**
- Budget-aware nudge of quality-slot ordering when budget currency matches the pair
- Currency-safe budget amount for scoring (`resolveScoringBudgetAmount`)
- New module: `lib/packages/candidates.ts`

---

## 4. Diversity improvements (Sprint 16.3)

- Deterministic greedy diversity selection **after** scoring
- Exact `flightId + hotelId` duplicate suppression
- Default repetition caps: same flight ≤2, same hotel ≤2 when the pool can fill the result set; caps scale when the pool is too small
- Top-5 targets when pool allows: ≥3 unique flights, ≥4 unique hotels
- `MAX_PACKAGES` remains 20; `PACKAGES_INITIAL_VISIBLE` remains 5
- New module: `lib/packages/diversity.ts`

---

## 5. Recommendation explainability (Sprint 16.4)

- Exactly one **Recommended** role among the visible top five (highest score)
- At most one secondary role per card, assigned deterministically from package data + optional budget
- Roles: Recommended · Lowest price · Best hotel · Best value · Fastest · Direct flight · Fits your budget
- Short evidence-based reason lines (e.g. “Direct flight · 5★ hotel”)
- No raw scores, no “Match 73.4”, no AI-generated copy
- New module: `lib/packages/explanations.ts` (render-time; `TravelPackage` model unchanged)

---

## 6. Honesty gates (Sprint 16.5.1)

| Label / phrase | Gate |
|----------------|------|
| Best hotel | `hotel.stars >= 3` |
| “highly rated” | `stars >= 3` and `rating >= 4.5` |
| Fastest | ≥ 45 minutes shorter than the next distinct duration |
| Lowest price | ≥ 5% relative advantage vs the next price `(next − lowest) / next` |

If a gate fails, the role or phrase is omitted — not replaced with invented marketing copy.

## 8. Known limitations

- **Same-airline near-duplicates:** Multiple British Airways / Delta / Emirates offer IDs with similar duration and price can still appear together in the top five. Diversity is identity-based (`flightId` / `hotelId`), not airline-similarity based. **Not fixed in v0.21.0.**
- SerpAPI RT `departure_token` outbound fallback (carry-forward)
- Hotel `children_ages` default `8`; no multi-room hotel query
- No FX conversion; budget roles/warnings are currency-safe
- Booking / payment / AI recommendations are out of scope
