# Glooconn v0.16.0 — Release Notes

**Release date:** July 2026  
**Codename focus:** Search Experience (Milestone 10)  
**Preceded by:** [v0.15.0](./v0.15.0.md) (multi-provider flights + SerpAPI)

---

## Highlights

- **Professional search results UI** — loading skeletons, clear headers, empty/error states, no mock-provider wording
- **Partial provider failure** — one domain can fail without blanking the search (`SearchResponse` + warnings, ADR-037)
- **Richer client filters & sorting** — stops, cabin, airlines, stars, amenities, operators; Recommended / Cheapest / Fastest / Highest rated / Best value
- **Deterministic result ranking** — price, rating, journey, stay quality + budget fit (no AI)
- **Client search performance** — stable cache keys, short-lived result TTL, in-flight dedupe, debounced filters/autocomplete
- **Destination autocomplete quality** — IATA / name / country / whole-word ranking, Cities/Airports grouping, match highlight
- **Accessibility hardening** — combobox ARIA, unique CTA labels, filter panel wiring, focus styles

## New UX

- Results header + summary chips; empty and error states with Edit search / Try again / Clear filters
- Warnings banner for partial provider unavailability (provider-agnostic copy)
- Filter sidebar facets derived from the current result set
- Destination suggestions with highlighted matches and airport grouping when typing IATA-like queries
- Budget remains a required numeric input with currency selector

---

## Reliability improvements

- Orchestrator uses `Promise.allSettled` for hotels / flights / transport
- Optional `warnings[]` on successful `SearchResponse`
- Hard failure only when every requested domain fails (or validation fails)

---

## Performance improvements

- Stable `buildSearchCacheKey` (sorted `productTypes`, canonical fields)
- ~45s client TTL + in-flight dedupe for `POST /api/search`
- `useServiceQuery` keeps previous data while loading
- Debounced destination filter (~160ms) and price filter commits (~200ms)
- Memoized result cards

---

## Architecture improvements

- Live search success payload is `SearchResponse` (not a flat result array) — ADR-037
- Client destination ranking lives in `lib/destinations/rank.ts` (provider helpers unchanged)
- Client result ranking lives in `lib/results/rank.ts`
- No changes to `SearchRequest`, provider interfaces, factories, or registries in Milestone 10 quality/performance sprints

---

## Breaking changes

**None** for API consumers.

- `POST /api/search` success body remains `SearchResponse` (introduced in Sprint 10.2 / already part of the live contract before this release tag)
- Default mock mode behavior unchanged

---

## Migration notes

No migration required for local/CI defaults (`USE_MOCK_PROVIDERS=true`).

If you already consume `SearchResponse` from Sprint 10.2, continue as before:

```ts
const result = await postSearchTrips(search);
if (result.success) {
  const { hotels, flights, buses, trains, warnings } = result.data;
}
```

Provider env flags are unchanged from [v0.15.0](./v0.15.0.md).

---

## Known limitations

- `/destinations` and `/about` pages still 404 (nav links present)
- Hotels / activities live providers not yet connected
- SerpAPI remains **dev/test only** (ADR-036); Amadeus is the long-term production flights path
- `currencyService` still uses mock provider directly (ADR-035 debt)
- Manual Amadeus sandbox checklist not yet executed as a formal QA pass
- Result CTAs (View deal / Select flight / …) are UI placeholders — booking flow not implemented
