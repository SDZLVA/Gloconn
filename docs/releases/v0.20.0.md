## Release overview

v0.20.0 closes Milestone 14 (MVP UI simplification) and Milestone 15 (MVP Conversion) together. The focus is making the existing product **trustworthy and clearly communicative** before adding new capabilities.

A new user can now:

1. Search flights + hotels from a clean, focused form
2. Receive up to 5 Recommended Packages with honest pricing and a quality badge
3. Understand exactly what a package price covers ("Flight per person + hotel N nights, 1 room — est. total")
4. See whether their budget is compatible with available packages
5. Browse individual flights and hotels with clear per-person and per-room labels
6. Edit or save their search

No booking, payment, or AI features are included. All prices are informational estimates.

## What changed from v0.19.0

### Milestone 14 — MVP UI simplification

- Search form now shows only the fields relevant to the MVP: From, Destination, Dates, Travelers, Budget, Flights + Stays
- Hidden (architecture retained): Travel Style, Rooms stepper, Transport toggles/results/filters
- Removed from UI: Destinations/About nav links, fake booking CTAs
- UX additions: origin ↔ destination swap control; dynamic "Budget (EUR/USD/…)" label; trip-type wording ("one-way / round-trip")
- Browse Flights / Browse Hotels hierarchy on results page
- Mobile auth menu parity

### Milestone 15 — MVP Conversion

#### Pricing clarity (Sprint 15.2)

- **Flight cards** — price suffix changed from "total" to **"per person"** on both individual flight cards and inside package flight boxes
- **Hotel cards** — price label reads **"N nights · 1 room"** on both individual hotel cards and inside package hotel boxes
- **Package footer** — reads **"Flight (per person) + hotel (N nights, 1 room)"** with an **"est. total"** price suffix; makes the composition explicit and avoids implying a guaranteed all-in price
- **Quality badge** — **"Top Pick"** (score ≥ 80) or **"Good Match"** (score ≥ 60) replaces the opaque numeric score; packages below 60 show no badge
- **Hotel stars** — zero-star hotels now display **"Unrated"** instead of an empty space
- **Multi-room warning** — shown when the adult count exceeds 2, noting that one room may not be sufficient

#### Recommended Packages UX (Sprint 15.3)

- Packages capped at **5 visible initially** with a **"Show N more packages"** toggle; the full composer output is available on demand
- **"What's included"** one-line summary per card: "Flight + N nights at Hotel Name"
- **Result counts** ("12 flights · 20 hotels") displayed in the sort bar
- **Flight route context** ("LHR → CDG") shown on both flight cards and package flight boxes when IATA codes are available; omitted entirely when unavailable — no placeholder invented
- **One-way hotel warning** — if a one-way search produces no hotel results (hotels require a checkout date), a clear explanatory banner is shown instead of the generic provider-unavailable message
- **Quality-aware candidate pool** — PackageComposer now builds its candidate set from the 6 cheapest options plus the 2 highest-rated options not already in that set (replacing a purely cheapest-first approach); scoring and sorting are unchanged

#### Budget (Sprint 15.4)

- **Budget is now optional** — leaving the field empty is valid; the form submits without a budget constraint and `SearchRequest.budget` is `null`
- **BudgetSelector layout** — currency selector and budget input appear **side-by-side on desktop/tablet** (`md:` breakpoint and above); stacked vertically on mobile to prevent overflow
- No required asterisk; placeholder reads **"Any budget"**
- `validateBudget` accepts an empty string as valid; `buildSearchRequest` maps it to `null`

#### Budget compatibility warning (Sprint 15.4)

- A **non-blocking informational banner** appears above Recommended Packages when:
  - The user set a budget
  - At least one package shares the budget's currency
  - Every package in that currency exceeds the budget
- The banner reads: *"Your budget may be too low for this trip. Try increasing your budget to see more suitable options."*
- Results are **never hidden** — all packages, flights, and hotels remain visible
- **Currency-safe** — the warning is suppressed when no composed package uses the same currency as the budget (no FX conversion is performed)
- Logic lives in `shouldShowBudgetCompatibilityWarning` in `lib/results/packagesUi.ts` — pure, fully tested

## Known limitations

These are carry-forward items tracked for future milestones — they do not block v0.20.0:

- **SerpAPI round-trip `departure_token`** — return-leg enrichment may fall back to outbound-only pricing; affects round-trip flight price accuracy
- **Hotel `children_ages` default** — SerpAPI hotels provider defaults `children_ages` to `8`; no user-facing configuration yet
- **One-way proactive note** — the budget warning for one-way + hotel searches appears after submission; a pre-submission note in the form was identified but deferred
- **`SectionHeading` hydration warning** — cosmetic dev-overlay warning; no production impact
- **currencyService DI debt (ADR-035)** — `currencyService` imports `mockCurrencyProvider` directly to avoid pulling `server-only` through the provider registry on the client
- **`travelStyle` dead validation** — `validateSearchForm` validates a hidden field that is always set to `"standard"`; unreachable through any live UI path
- **Budget amount = 0 edge case** — entering `0` passes validation and triggers the compatibility warning for all non-zero packages; very low real-world frequency

## Configuration notes

No new environment variables in v0.20.0. Existing configuration is unchanged:

| Variable | Purpose |
|---|---|
| `USE_MOCK_PROVIDERS` | `true` (default) — no live API calls needed for local dev |
| `FLIGHTS_PROVIDER=serpapi` | Enable live SerpAPI flights |
| `HOTELS_PROVIDER=serpapi` | Enable live SerpAPI hotels |
| `SERPAPI_API_KEY` | Required when live SerpAPI is active |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Required for auth and saved trips |

No schema changes. No database migrations required.
